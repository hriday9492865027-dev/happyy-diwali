# Frontend Design Rules

- Follow the DEEPAVALI visual direction: cinematic dark background, warm gold/amber highlights, subtle maroon accents, elegant typography, and restrained festive detail.
- Prioritize the visitor's portrait and greeting hierarchy. The face must remain visible and must not be persistently covered by effects or text.
- Use design tokens / CSS variables for colors, spacing, radii, shadows, and motion timings. Avoid scattered arbitrary values.
- Create reusable components for the page shell, upload panel, portrait preview, greeting scene, particle canvas, controls, and admin UI.
- Prefer polished, purposeful composition over generic dashboard cards or excessive glassmorphism.
- Provide clear hover, focus, pressed, disabled, loading, and error states.
- Use semantic HTML and accessible labels. Icon-only controls need accessible names.
- Do not use the random online sample photo from the design conversation as an asset. Use abstract placeholders or explicitly licensed/consented test assets.
- Do not fabricate visual assets or imply a feature works when it is only a mock.
